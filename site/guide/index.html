Guide

Getting started

Manovella makes product films as code inside a coding agent, Claude Code, Codex, Copilot CLI or Gemini CLI: promo loops, teasers, tutorials and release films, built from your product’s own brand and interface.

What it is

A film is one HTML page whose seek(t) draws the frame at time t from scratch. Headless Chrome captures the page frame by frame, sixteen subframes each, and ffmpeg blends and encodes them. The film is a function and the video a sampling of it, so any frame can be reviewed as a still, a change costs a re-render of what changed, and a loop closes to the pixel.

You ask for a film in words, or brief it in the Studio. Claude answers with three storyboards, then stills, and renders only when you say go. Nothing renders on its own.

Manovella is Italian for the hand crank of an old film camera, the one that advances the film frame by frame.

Requirements

  • macOS on Apple Silicon, Manovella’s home, or Linux and Windows.
  • A coding agent: Claude Code, or Codex CLI, GitHub Copilot CLI or Gemini CLI.
  • Node (tested with 24.3), ffmpeg (tested with 9.0.2) and Google Chrome. The renderer drives Chrome through playwright-core, installed in each film’s work folder: nothing else is downloaded. With Homebrew: brew install node ffmpeg.
  • Xcode Command Line Tools (swiftc), optional: for the Studio’s own window and the chip’s thermometer. Without them the Studio opens in a Chrome app window, and renders are held on macOS’s thermal state.
  • Voices, optional. Python 3.13 on a Mac (3.12 elsewhere) and a one-time setup (see Sound). Without them a film speaks with a macOS voice, or not at all.

On Linux and Windows

The engine, the Studio and the renders run on Linux (Windows through WSL2 too) and on Windows as well, and CI runs them on both. What changes there:

  • Node, ffmpeg and Chrome: on Linux apt install ffmpeg (or your distribution’s) and Google Chrome, or Chromium where Chrome has no build (linux-arm64); on Windows winget install OpenJS.NodeJS.LTS, winget install Gyan.FFmpeg and winget install Google.Chrome. A machine without a GPU draws the shader looks and cuts in software: slower, the same frames.
  • The Studio opens in a Chrome app window (the window app is the Mac’s), or in the default browser.
  • Renders run at below-normal priority, with a heat governor on Linux and none on Windows: see Rendering.
  • The Trash: on Linux gio or trash-cli; on Windows the Recycle Bin.
  • Voices: the voice models run on PyTorch from a Python 3.12, Chatterbox and Orpheus best on an NVIDIA GPU; the macOS voices are the Mac’s. See Sound.
  • Type: SF Pro and SF Symbols are licensed for Apple platforms only, so a film of a Mac app is made on a Mac. Web products and command-line tools are not affected.

Install

In Claude Code, Manovella is a plugin with a marketplace of its own:

claude plugin marketplace add gfazioli/manovella
claude plugin install manovella@manovella

To update by hand, run claude plugin marketplace update manovella and then claude plugin update manovella@manovella. Or declare it in ~/.claude/settings.json (merged into what is there) and Claude Code keeps the plugin current: { "extraKnownMarketplaces": { "manovella": { "source": { "source": "github", "repo": "gfazioli/manovella" }, "autoUpdate": true } } }.

Other coding agents

The engine is Node, Chrome and ffmpeg, and the instructions are two Agent Skills, so three other agents install Manovella too. How good a film is follows the agent’s model. The installs are tested, and in Copilot CLI so is a film’s way from the Studio to its stills; Codex and Gemini CLI are next (#1). This guide says Claude for the agent: in another one, read its name.

AgentInstall
Codex CLIcodex plugin marketplace add gfazioli/manovella, then codex plugin add manovella@manovella
GitHub Copilot CLIcopilot plugin marketplace add gfazioli/manovella, then copilot plugin install manovella@manovella
Gemini CLIgemini extensions install https://github.com/gfazioli/manovella, and gemini extensions update manovella to update

For the Studio, ask Codex or Copilot CLI for Manovella’s Studio; Gemini CLI has /manovella:studio.

A film installs packages and voice models from the network, writes its work folder outside the project, starts Chrome and the Studio, and renders for minutes. Give the agent room for that:

  • Codex: its default sandbox (no network) asks at every such command; approve them, or start it with --sandbox danger-full-access for a film.
  • Copilot CLI: --add-dir ~/Downloads (or --allow-all-paths) and --allow-all-urls, or --allow-all for both.
  • Gemini CLI: it asks before each tool; --approval-mode auto_edit approves its file edits, yolo every tool.
  • Every agent: a render at 1080p60 takes about 29 times the film’s length, so the shell’s command timeout must allow it, or the render goes on detached and resumes with RESUME=1.

The window app

On a Mac the Studio opens in a small app of its own, built once per Mac (and again after a change to the window kit or to studio.json). Without it the Studio opens in a Chrome app window.

S=$(ls -d ~/.claude/plugins/cache/manovella/manovella/*/skills/site-promo-film | sort -V | tail -1)
"$S/studio/window/build.sh" "$S/studio"     # installs ~/Applications/Manovella.app

In another agent the skill is elsewhere: ~/.codex/plugins/cache/manovella/manovella/<version>/skills/site-promo-film (Codex), ~/.copilot/installed-plugins/manovella/manovella/skills/site-promo-film (Copilot CLI), ~/.gemini/extensions/manovella/skills/site-promo-film (Gemini CLI).

A first film

Three ways in, in Claude Code. In another agent, ask in words; Gemini CLI has /manovella:studio too.

AskWhat happens
/manovella:studioThe Studio, ending in a brief that Claude answers with three storyboards.
/manovella:site-promo-filmA promo, launch, teaser, tutorial or explainer film of a product, site or app. ? is the guided mode.
/manovella:release-filmA “what’s new” film of one release, the changed surfaces rebuilt from the app’s source at the tag.

Or just ask: “a 15 s promo loop of acme.app, 16:9 and 9:16, with our music”. Claude fills what you leave out with a default, asks what it cannot guess, and waits for you at the storyboards, at the contact sheet and at the delivery. Making a film walks through each step.
